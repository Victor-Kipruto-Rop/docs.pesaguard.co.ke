Idempotency Live

Webhook deliveries can be retried or replayed. Deduplicate by the stable event identity and ensure that processing the same event again does not repeat a financial effect.

  1. Verify the signature before accepting an event.
  2. Persist the event identity and processing outcome durably.
  3. Apply business effects once; return an acknowledgement only after the receiver has accepted the event according to its policy.
  4. Make replay safe by returning the recorded outcome for an already-processed event.

See the idempotency concept, retry guidance, and the delivery lifecycle.
