Environments

Staging and production are distinct intended environments with separate data, credentials and operational risk. This documentation describes the boundaries and verification steps; it does not assert either deployment is currently reachable or ready.

Environment status: verification required

Confirm the base URL, effective configuration and operator-provided evidence before using either environment.

Environment selection checklist

  1. Confirm the base URL and DNS or tunnel target.
  2. Confirm the credential belongs to the same environment and tenant.
  3. Check database, Redis and Kafka endpoints before starting workers.
  4. Use synthetic or approved data in staging; never copy production secrets into it.
  5. Run an authenticated health or read check before enabling writes.

Promotion path

Promote configuration and application artifacts through staging before production. Re-run migrations, contract tests, retry tests and reconciliation checks in the destination environment. Promotion means issuing destination credentials and validating destination dependencies, not copying a .env file.

Settings live in the git-ignored root .env. Validate with config --quiet; bring up with up -d --build only after reviewing the merged configuration. Full list: environment variables.
